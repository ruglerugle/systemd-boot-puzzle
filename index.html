systemd とは?

Linuxが起動するとき、OSはたくさんの「やること」を順番に立ち上げていく。たとえば「ファイルシステムをマウントする」「ネットワークに繋ぐ」「データベースを起動する」「Webサーバーを起動する」など。 これらの「やること」をひとつひとつ管理しているのが systemd というプログラムだ。

各「やること」は unit（ユニット） という単位で管理される。主に2種類ある。

種類意味
.service実際に動くプログラム（例: sshd, nginx, mysql）
.target複数のunitをまとめた「節目」「グループ名」。プログラムそのものは動かさない

重要なのは「順番」だ。例えばWebサーバー(nginx)はデータベース(mysql)より先に起動しても意味がない（DBに繋がらず動かない）。 そこでunitは他のunitに対して 依存関係 を宣言する。

依存の種類意味
Requires（硬い依存）依存先unitが起動済みでなければ、このunitは起動できない（失敗する）
Wants（柔らかい依存）依存先unitも一緒に起動しようとするが、依存先が無くても・失敗していても自分は起動を続ける
After依存先unitの後に起動する、という順序だけの指定（成功/失敗は問わない）

このゲームでは Requires の依存先が active になっていないunitを起動しようとすると failed になる。 一方 Wants の依存先が無くても、本体のunitは起動に成功する（ただし警告ログが出る）。これが実際のsystemdでの大きな違いだ。

また「今すぐ起動する」と「次回起動時から自動的に立ち上げる」は別の概念だ。

コマンド意味
systemctl start 名前今すぐそのunitを起動する（再起動すると消える）
systemctl enable 名前次回OS起動時から自動的に立ち上げるよう設定する（今すぐは起動しない）
systemctl status 名前そのunitの現在の状態（active/failed、有効化されているか等）を確認する
journalctl -u 名前そのunitに関するログ履歴を見る。failedの原因調査に使う

このゲームでは下の入力欄に本物に近いコマンドを打ち込んで操作する。ゴールは依存関係を正しい順番で解決し、最終的に multi-user.target（「ログインしてマルチユーザーで使える状態」を表すターゲット）に到達することだ。

systemd 起動パズル

下の入力欄に systemctl start 名前 のような本物のコマンドを打って操作する（カードクリックでも起動できる）。
Requires の依存先が active でないと起動は failed になる。Wants の依存先は無くても起動できる（柔らかい依存）。
すべてのユニットを起動し、multi-user.target に到達せよ。各カードの?アイコンで解説が見られる。
使えるコマンド: systemctl start|stop|enable|disable|status <名前> / journalctl -u <名前>
